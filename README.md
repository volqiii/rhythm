# Ритм

> Личный трекер регулярности: календарь, цель и один аккуратный коммит за новый день.

**Ритм** — небольшой статический проект для тех, кому важно видеть регулярность без таблиц и ручного подсчёта. Страница показывает цель, текущую серию, последнюю отметку и весь календарь года.

## Что умеет проект

- отмечает новый календарный день только один раз;
- ведёт цель на 70 уникальных дней;
- показывает прогресс на статичной странице без базы данных;
- запускается автоматически в 00:05 по Екатеринбургу;
- отправляет Telegram-уведомление только после реального нового коммита;
- работает на GitVerse и GitHub Actions.

## Как это устроено

Все данные лежат в одном понятном файле: [`public/data/checkins.json`](public/data/checkins.json). Workflow запускает [`scripts/mark-today.mjs`](scripts/mark-today.mjs), добавляет сегодняшнюю дату и делает коммит. Сайт читает этот файл и сразу обновляет прогресс.

По умолчанию расписание рассчитано на учебный ритм — **понедельник–пятница в 00:05 по Екатеринбургу и ещё одно воскресенье раз в две недели**. После достижения 70 дней workflow спокойно завершится без новых коммитов.

## GitVerse: запуск за несколько минут

1. Создайте публичный репозиторий и загрузите проект.
2. В **Настройки → Репозиторий** включите CI/CD.
3. В **Настройки → Страницы** выберите ветку `master` и папку `/public`.
4. В **Настройки → Секреты и переменные** добавьте:

| Секрет | Что указать |
| --- | --- |
| `COMMIT_AUTHOR_NAME` | Логин GitVerse |
| `COMMIT_AUTHOR_EMAIL` | Подтверждённый email из профиля GitVerse |
| `TELEGRAM_BOT_TOKEN` | Токен, выданный BotFather |
| `TELEGRAM_CHAT_ID` | Числовой ID чата, куда придёт уведомление |

5. Откройте вкладку **CI/CD → Daily check-in** и при желании выполните один ручной запуск. Если отметка за текущий день уже есть, workflow закончит работу без нового коммита — это ожидаемая защита от дублей.

## GitHub: как использовать тот же проект

В репозитории уже есть workflow [`.github/workflows/daily-checkin.yml`](.github/workflows/daily-checkin.yml). Чтобы включить GitHub-версию:

1. Создайте публичный репозиторий на GitHub и загрузите туда эту же папку.
2. В **Settings → Actions → General** разрешите `Read and write permissions` для workflow.
3. В **Settings → Secrets and variables → Actions** добавьте те же четыре секрета из таблицы выше.
4. На вкладке **Actions** откройте `Daily check-in` и запустите его вручную для проверки.

GitVerse и GitHub хранят свои календари независимо друг от друга. Если включить оба workflow, в каждом сервисе будут появляться собственные коммиты и собственная карта активности.

## Настройка под себя

- **Цель:** измените `targetDays` в `public/data/checkins.json`.
- **Часовой пояс:** замените `Asia/Yekaterinburg` в `scripts/mark-today.mjs` и `public/index.html`, затем обновите UTC-время в обоих workflow.
- **Расписание:** отредактируйте cron в `.gitverse/workflows/daily-checkin.yml` и `.github/workflows/daily-checkin.yml`.
- **Дизайн:** основная вёрстка и цвета находятся в `public/index.html`; никаких внешних библиотек не требуется.

## Безопасность

Токены, пароли и email не должны попадать в коммиты. Для них предусмотрены секреты репозитория. Если токен Telegram случайно оказался в открытом доступе, сразу отзовите его через BotFather и создайте новый.
